🛠️ The Kubernetes Observability Cheat SheetProject: 07-health-api-k8s1. The "Traffic Light" Check (The Hierarchy)If Prometheus shows a target as DOWN, follow this sequence. Never skip a step.RED 🔴 (Pod Level): kubectl get podsGoal: Status must be Running.Fix: Check logs (kubectl logs <pod>) if it’s crashing.ORANGE 🟠 (Service Level): kubectl get endpoints <service-name>Goal: Must show an IP address (e.g., 10.244.x.x:80).Fix: If <none>, your Service selector doesn't match your Pod labels.YELLOW 🟡 (Monitor Level): kubectl get servicemonitor -n monitoringGoal: matchLabels must match the Service labels.Fix: Ensure release: monitoring (or your Prometheus selector) is present.GREEN 🟢 (Data Level): Check the Error in Prometheus UI.Goal: Status UP.Fix: If "Connection Refused," check your targetPort. If "Content-Type" error, ensure the app is sending plain text, not HTML.2. The "Labels" Golden RuleLabels are the "glue" of Kubernetes. For Prometheus to work, three things must match:The App: labels: { app: health-api }The Service: selector: { app: health-api }The Monitor: selector: { matchLabels: { app: health-api } }Note: If one of these is even slightly different (e.g., health-api vs health-api-svc), the whole chain breaks.3.
